05 / THE METRIC IS A DEFINITION
Read the numerator.
RankParentJudgedGradeHitGainDiscountDCG termCumulative DCGHits
The ideal denominator
RankDocumentGradeGainDiscountDCG term
Positive grades count as relevant. Precision divides by requested k, even when fewer parents return. Recall divides by all positively judged documents, including absent ids. Unjudged results get grade zero, not a claim of irrelevance. Gain is 2^grade - 1; discount is 1/log2(rank + 1). RR here is cut at k; the original library evaluates all supplied ranks, while the CLI supplies only its cutoff. Queries without positive judgments are excluded from the original macro average, not counted as zero-quality queries.


06 / CONTROLS AND LIMITS
A perfect score can hide a thin judgment set.
The original 12-document, six-query corpus and all 42 tests remain. Its illustrative perfect recall is retained, not presented as a general retrieval result. New controls expose duplicate chunk crowding, out-of-corpus judgments, zero-score ties, repeated query tokens, overlap and cutoff denominators.
BM25 and ranked metrics are prior work. This implementation uses its stated positive-IDF formula, linear repeated-query weighting and no stopword removal or stemming. It does not claim Lucene score parity. Whole-document versus chunk indexing changes corpus statistics; this is not an isolated test of chunk text quality. Overlapping tail windows are retained from the original implementation.
Parent ids are carried as data, never guessed from a '#c' delimiter. Duplicate unit ids and judgment pairs are rejected. Duplicate metric rankings are rejected rather than inflating recall/nDCG. Nonfinite parameters/gates are rejected; high-grade nDCG uses scaled gains to avoid overflow outside this bounded inspector.
